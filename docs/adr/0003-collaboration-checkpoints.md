# Durable collaboration, checkpoints, and private comments

Status: design resolved. Native storage, authenticated transport, official comment commands, opt-in application startup and the supplied collaborative client are implemented on the integration branch. The retained preview remains in solo mode while the remaining activation gates are completed. [Validation](../../VALIDATION.md) records current results; earlier preparation notes below describe their checkpoints. This decision extends [ADR 0001](0001-native-blocknote-documents.md) and preserves [selected publication](0002-integration-storage-and-publication.md).

## Storage and visible meaning

Use the existing Yjs 13.6.33 and y-prosemirror 1.3.7 baseline, BlockNote 0.55.0's `@blocknote/core/yjs` entry point, and maintained Hocuspocus server/provider 4.7.0. Do not mix the separate `@blocknote/core/y` entry point, which targets Yjs 14 release candidates. Hocuspocus is MIT; BlockNote's collaboration, comments, React components, and shadcn integration remain MPL-2.0. Existing XL exporters retain their GPL OSS licensing path. No paid collaboration or AI service is needed.

One enabled collaboration process owns rooms for a database/schema. Hold a PostgreSQL advisory lease for that ownership; a second process refuses activation, and losing the lease closes rooms. Multiprocess room replication and Redis are outside this implementation.

| State | Representation | Changes |
| --- | --- | --- |
| Live body | Y.XmlFragment `document` | Authorized collaborative edits |
| Live title | Y.Text stored at `metadata.title` in a Y.Map | Character edits, not whole-string last-writer replacement |
| Private comments | Official thread representation in Y.Map `threads`, with native comment marks in the live fragment | Authorized comment operations |
| Immutable checkpoint | Existing native BlockNote envelope and title in DocumentRevision | Explicit Save or restore |

Persist a full Yjs V1 encoded state per `(documentId, roomEpoch)`, with a monotonic accepted-update sequence and a live-storage schema version. Keep old epochs when restore advances the current pointer. `roomEpoch`, live sequence, content revision number, lifecycle lockVersion, and publication availabilityVersion have separate meanings. Never regenerate an established room from Block[] on reconnect: BlockNote's own conversion utilities warn that this loses CRDT history. Initial enrollment derives its state from the current authorized checkpoint while holding the space and document locks. Reader enrollment can initialize that server-derived representation but cannot supply authored content.

Once a document uses live storage, ordinary REST title/body PATCH must refuse competing snapshot replacement. Enrolling advances its lock version so an older solo client cannot silently commit against its former baseline. New document creation and documents outside live mode retain their existing behavior.

The primary Save action creates a checkpoint of the server's durable live title and body. It requires the existing document ETag, current epoch, and observed live sequence. Missing preconditions return 428; stale values return 412. Capture title/body and attachment references in the existing authorized transaction. Canonical no-op checkpoints create no revision. Transport synchronization is displayed as "Synced"; only a successful checkpoint is described as saved history. Live changes do not update search or publication until a checkpoint is saved. Default native/PDF/DOCX export reads the selected checkpoint, never an uncheckpointed room.

## Commit before broadcast

Hocuspocus 4.7.0 awaits `beforeSync` before applying SyncStep2/update payloads and emitting their acknowledgement. Its document callback broadcasts changes without awaiting `onChange`, and `onStoreDocument` is normally debounced. Therefore a database extension's delayed store hook alone cannot prove durability before acknowledgement. The current hook documentation calls `beforeSync` non-async; the pinned source and observed runtime contradict that sentence. Use the pinned implementation, with a regression test protecting this seam. [Pinned receiver](https://github.com/ueberdosis/hocuspocus/blob/6ddc75775b22fea83fab15cb7c8f9c84a45556f6/packages/server/src/MessageReceiver.ts), [document fan-out](https://github.com/ueberdosis/hocuspocus/blob/6ddc75775b22fea83fab15cb7c8f9c84a45556f6/packages/server/src/Document.ts), [hook documentation](https://tiptap.dev/docs/hocuspocus/server/hooks).

Use one room mutex across inbound messages, checkpoint, restore, and server comment mutations. Acquire it in `beforeHandleMessage`, release it in `afterHandleMessage`, and release it explicitly if the first hook rejects. Hocuspocus's queues serialize a connection, not all clients of a room. Disable delayed document fan-out with `flushDelay: false`.

For each mutation, clone the current complete Yjs state, apply the proposed update to the clone, validate it, and commit its encoded state before returning from `beforeSync`. Core owns the transaction and current authorization. Keep the existing space-before-document database lock order, followed by stable user/session row locks. Recheck both the sender and connected recipients; hold their user/session rows with share locks until acceptance commits. Remove recipients that no longer have access before fan-out. Membership revocation takes the same space lock, and session deletion/role changes conflict with the relevant row locks. This gives accepted updates a definite ordering with revocation, including operator recovery in another process. Bytes already accepted or queued cannot be recalled.

Reject unknown roots, unsupported live node/attribute/mark shapes, foreign attachment references, unsafe URLs, and incomplete CRDT dependencies before persistence. The latter check uses the exposed StructStore pending fields of the pinned Yjs version and needs a regression test: a deferred hidden update must not become a comment mutation during a later trusted transaction. Bound frames to 1 MiB and encoded room state to 8 MiB; preserve existing native body limits. The server live PM schema explicitly includes the official comment mark; the existing native parser validates its content projection.

The implemented preparation module uses `gc: false` for server-owned states and their validation clones, retaining deleted CRDT structures. It compares every protected thread Item's encoded representation, identity/length and deletion state before accepting a client update. Visible JSON equality alone is insufficient. Its tests include deleted/shadowed writes from both garbage-collecting and non-collecting clients, and pending insert/delete dependencies. Keep this pinned Yjs seam under regression coverage. Validation checks the raw live tree before conversion, then requires an exact native PM round trip after removing only the official live-only comment marks. Blank titles are temporarily permitted during character editing; checkpoint Save retains the existing nonempty title policy. Clients cannot replace the title's Y.Text or add title formatting/attributes.

On persistence failure, reject the frame without applying or acknowledging it. If commit acknowledgement is ambiguous, stop the room and reload durable state before accepting another frame. Do not infer rollback from the exception or overwrite storage from an older in-memory document. A crash after commit but before broadcast is recovered from encoded state on reconnect. `onStoreDocument` must not become an unvalidated parallel write path.

Server comment operations run the official store against a clone and pass through this same authorization, validation, and commit sequence. Applying a direct Hocuspocus transaction first would broadcast before its database write, so it is not the persistence boundary.

## Connections, revocation, and unsent work

Mount the maintained WebSocket transport on the application origin, using Hocuspocus's public connection API; do not open a public second service or rely on example WebRTC/broadcast channels. Require the configured Origin on upgrades and resolve the existing Better Auth cookie session on authentication. Never put sessions or credentials in room names, URLs, logs, or browser storage. Reader connections are server read-only; archived documents deny writes.

Every inbound message, initial synchronization, and accepted server mutation checks current session, role, space access, lifecycle, and epoch. Awareness identities come from the authenticated server principal, not client-supplied user IDs/names. Eager connection invalidation after core grant changes/logout and expiry timers improve prompt feedback; the per-operation recipient checks remain authoritative when account recovery happens in a separate process. Session expiry closes passive connections without waiting for their next keystroke. Hook exceptions are sanitized because upstream logs hook errors outside Fastify's problem handler.

Connection loss pauses editing and retains the complete draft only in memory. The implemented client deliberately creates a fresh Y.Doc on every reconnect, including the same epoch. It keeps the former complete title/body separately for comparison and native draft download, and never replays the old update queue or retries a failed checkpoint or stale REST save. Access loss or a reader downgrade destroys the writing provider and opens a fresh read-only document only after authorization. Keep unsent title/body separately as a private in-memory draft, with server actions disabled. Do not inject it into the new read-only provider. Epoch changes always create a fresh Y.Doc; keep the former draft separately for deliberate reconciliation, never automatic replay. Do not add IndexedDB, localStorage, or other persistent private-content caches.

## Undo, discard, restore, and archive

Solo editing retains baseline Discard changes. Live editing has local undo/redo and "Undo my changes", never whole-document baseline replacement or a bulk rollback of all edits since Save. Title and body share one Y.UndoManager scoped only to their types. Track the local PM origin and this editor's title origin; exclude remote/provider, server comment, initialization, and restore origins. Keep `ignoreRemoteMapChanges: false`.

The supplied default YUndoExtension is insufficient for this contract. An observed runtime test showed that undoing a locally created blockContainer deleted a peer's later text inside it. y-prosemirror's default filter protects paragraph nodes but not their parents. Replace only that extension's configuration, using the official `yUndoPlugin`, commands, UndoManager, and `defaultDeleteFilter`, with protectedNodes covering all native structural PM nodes. A configured runtime proof retained peer work through paragraph, heading, table, and title undo/redo. Actual BlockNote browser coverage remains an activation gate. [BlockNote undo extension](https://github.com/TypeCellOS/BlockNote/blob/v0.55.0/packages/core/src/yjs/extensions/YUndo.ts), [official undo plugin](https://github.com/yjs/y-prosemirror/blob/v1.3.7/src/plugins/undo-plugin.js).

Restore requires a clean checkpoint of current live content first; it must refuse uncheckpointed shared changes rather than erase them or silently add an extra revision. After deliberate confirmation, append the restored native revision and initialize a new roomEpoch from it in one core transaction. Retain the old encoded room, close its connections, and reject old-room updates/reconnects. Clients must not retarget an old Y.Doc to the new room. Yjs update bytes do not intrinsically identify an epoch; enforcement is through authenticated room identity and fresh-client reconstruction. A currently authorized editor can still deliberately author replacement content. The upstream Yjs 13 versioning adapter explicitly throws for applyRestore, so use the server epoch operation and the existing authorized history workflow. [Pinned restore limitation](https://github.com/TypeCellOS/BlockNote/blob/v0.55.0/packages/core/src/yjs/extensions/Versioning.ts).

Archive stops writes and closes editor connections while preserving durable live state and immutable history. Unarchive requires fresh authorization and a fresh provider; it must not release an old rejected update queue. Existing availabilityVersion publication invalidation remains unchanged. Publishing always approves a selected immutable checkpoint and its attachment allowlist. It never exposes live state, awareness, comment text, or comment authors.

## Comments and content versions

Use the supplied CommentsExtension, RESTYjsThreadStore, server-side YjsThreadStore, and official shadcn-backed floating/sidebar UI. Readers may view private comments but cannot create, reply, react, resolve, or edit them. Editors can create/reply/react/resolve, update their own comments, and remove a comment/thread under the supplied editor policy. Core repeats those checks and derives author IDs and timestamps from the current principal. Use the supplied default paragraph comment composer and validate that separate body shape; reject client metadata fields rather than accepting arbitrary identity/provenance objects.

Client Yjs writes must never mutate `threads`. Compare the candidate's protected thread state with its prior state, including deleted/hidden CRDT structures, not just visible JSON. Anchoring uses the official REST store's relative positions and a server transaction; stale/deleted selections fail clearly. Recheck thread/document/epoch ownership on every operation. Do not treat ThreadStoreAuth as server security: upstream explicitly describes it as UI visibility policy. The reader UI uses its small read-only policy adapter. [Official comment stores and authorization boundary](https://www.blocknotejs.org/docs/features/collaboration/comments), [pinned REST store](https://github.com/TypeCellOS/BlockNote/blob/v0.55.0/packages/core/src/yjs/comments/RESTYjsThreadStore.ts).

CommentMark explicitly declares `blocknoteIgnore: true`; the native node-to-block converter intentionally excludes it from Block[]. A runtime round-trip with a marked live paragraph preserved its text while excluding the thread ID from schemaVersion 1 native content. Thus comments and anchors stay in versioned private live storage, and the native checkpoint format remains unchanged. Do not add a fake comment style or silently accept unrelated marks. If comments are later included in snapshots/import/export, define a new explicit format/version first. [Mark contract](https://github.com/TypeCellOS/BlockNote/blob/v0.55.0/packages/core/src/comments/mark.ts), [native conversion](https://github.com/TypeCellOS/BlockNote/blob/v0.55.0/packages/core/src/api/nodeConversions/nodeToBlock.ts).

The user resolver returns only current users in the document's space, plus the authorized administrator, with display names and local avatar fallbacks. It must not become a global user directory or return emails. Removed authors display a neutral fallback. Scope and invalidate the supplied user cache with the document/session/grant; a stale cache is not authorization.

## Supplied client integration

`COLLABORATION_ENABLED` defaults false. Enabled startup claims the existing PostgreSQL ownership lease before attaching the same-origin socket capability. Readiness checks that lease; loss stops the process. Shutdown closes upgraded connections before HTTP shutdown, then releases the lease before closing the pool. `DB_POOL_MAX` must be at least 2 because the lease holds one connection. Enabling startup never enrolls existing documents. Authenticated `/api/v1/collaboration` reports actual availability.

The connected client uses `withCollaboration`, the supplied Hocuspocus provider, CommentsExtension, RESTYjsThreadStore, and official shadcn floating/sidebar components. It waits for authenticated synchronization before constructing BlockNote, preventing phantom initialization edits. Enrollment is explicit and requires a clean saved head. Initial and recovered connections read the current saved checkpoint before editing; failed state/head reads remain read-only until explicit retry.

The native UndoManager is configured during extension construction, while structural node protection is initialized after BlockNote mounts its PM schema. Title keyboard undo/redo uses that same manager. A metadata-only PM transaction refreshes the supplied undo command state after title changes, without producing body edits. It must not set `addToHistory: false`: the pinned native binding interprets that flag as a capture boundary and would split every typed character into a separate undo step. Live mode uses local undo instead of baseline Discard changes. Restore requires a clean checkpoint and a fresh epoch.

The pinned supplied sidebar opens its reply composer on thread focus without consulting write permission. A scoped component override makes that supplied editor and comment actions read-only when current authority is unavailable. The wrapper catches asynchronous mouse and keyboard submissions, retaining composer text and showing failure without claiming success. Native formatting and submit commands remain library operations. The supplied comment editor reports unsent text through its public change subscription, so navigation and reload guards cover comments independently of document edits. Comment Save submits that composer; document Save checkpoints title/body and does not submit comments. While a comment command is pending, composers become read-only through the public native setter and navigation waits for the response. Closing a composer, cancelling its edit, or a successful native submission clears its draft guard; a failed submission retains its complete text. The route blocker resets only when every kind of local work is clean, including comments and retained reconnect drafts. A narrow runtime check of the named public submit command avoids an incompatible optional-shortcut declaration in the pinned factory; no type check is suppressed.

The pinned REST store converts the selection after waiting for thread creation. The integration captures native Yjs relative positions before that request, then sends them through the existing typed anchor operation. This preserves the intended selection through intervening focus/content changes. The server validates ownership and current anchor positions. Creation and anchoring remain two native REST operations; failed anchoring can leave a private unanchored thread. There is no automatic create retry.

A retained reconnect draft participates in navigation/unload guards. It cannot be overwritten by another reconnect or restore until deliberately discarded; Keep editing preserves it. The current shared document and the retained title/body remain separate, with a complete native draft download. All private content stays in memory until an explicit user download. No persistent content cache or automatic reconnect is added. Awareness remains disabled until authenticated presence and recipient handling are verified.

## Activation gates

The inspected maintained OSS APIs support this bounded integration without forking the transport or rebuilding comments. Safe activation still requires application implementation and these real PostgreSQL/WebSocket/browser checks:

1. Two authenticated editors converge on standard blocks and concurrent title edits; a reader receives changes but crafted reader updates fail, and outsiders learn no room/title/content/presence/user details.
2. Delayed persistence emits no update or successful acknowledgement before commit. Failure, ambiguous commit, restart, and duplicate delivery preserve durable state without orphan checkpoints.
3. Concurrent clients cannot bypass room serialization. Malformed, oversized, incomplete, unknown-root, foreign-attachment, hidden-thread, and deferred comment mutations fail before fan-out.
4. Revocation, role downgrade, archive, logout, expiry, and separate-process account recovery stop subsequent document/comment/presence delivery using existing connections. Reconnect cannot restore authority or release rejected drafts.
5. Local undo/redo retains a peer's work in locally created paragraphs, headings, tables, nested blocks, and titles. It never restores a whole baseline over another editor's work.
6. Checkpoint ETag/epoch/sequence preconditions, no-op saves, concurrent checkpoints, mid-write rollback, revision ownership, and restore epochs preserve immutable history. Restore rejects uncheckpointed changes and old-room updates.
7. Official comment creation/anchors/replies/reactions/resolve work; forged authors and editing another author's comment fail. Reader controls remain read-only; cross-space user lookup and stale anchors reveal nothing.
8. Public snapshots and native/PDF/DOCX exports contain no threads, anchors, awareness, sessions, or live-only edits. Private attachments retain the existing document and selected-publication checks.
9. Disconnect/expiry/access loss preserve in-memory drafts honestly. Dirty navigation, deliberate reconciliation, narrow layouts, keyboard controls, and explicit saved-versus-synced feedback work in the actual UI, with no persistent content storage.

The preparation module has ten passing native/CRDT tests, including standard rich blocks/media/table geometry, concurrent title/body updates, exact state reload/idempotency, protected comment structures, unsafe/dropped content, pending dependencies, and resource limits. Private core room operations now add enrollment, read, durable update, checkpoint and restore. PostgreSQL/session tests cover concurrent merges/checkpoints, duplicate delivery, current grants and operator recovery while waiting for locks, attachment ownership, rollback of room/checkpoint writes, archive, retained restore epochs and deferred pointer ownership. An additive migration preserves populated solo documents and their history. The guarded fixture reset explicitly recognizes the new table and preserves the migration ledger.

Core storage has no product HTTP routes or frontend controls. The prepared transport is attached only by its real-socket tests. Core now locks the sender and supplied authenticated connection principals in stable user-before-session order. Its acceptance transaction returns only currently authorized connection IDs and their read/write status, omitting revoked/expired/foreign recipients. A read-only authorization operation supports the same check without exposing room bytes. Recovery uses the same lock order before the library revokes every account session. Real PostgreSQL tests include multiple sessions, downgrade, expiry and recovery blocked until acceptance commits. The prepared transport uses this receipt to disable unauthorized recipients before fan-out and apply current read-only status. Session lifetime is checked again after the candidate write and recipient checks, immediately before returning from the transaction. A genuine session expiring during an advisory-gated write caused an incorrect success in the new test; the corrected operation rolls back an expired sender and excludes recipients that expired during that wait. Row locks alone cannot prevent time-based expiry. The prepared gateway also checks expiry before every delivery and periodically closes passive expired/revoked connections. An isolated PostgreSQL ownership module now holds one dedicated advisory-locked connection per database/schema, rejects a second owner, and signals actual lease-connection loss. Real PostgreSQL 17/18 tests cover isolation, explicit handoff and termination of only the owned backend. The module is not wired into application startup yet. Prepared socket tests verify same-origin cookie authentication, commit-before-acknowledgement/broadcast, current recipient filtering, passive revocation/recovery, uncertain commit reload and lease-loss shutdown. Joining holds the room mutex through actual connection registration; shutdown awaits acceptance after socket removal. Failed initial loads destroy their unpublished awareness timer. Tests deliberately disable provider automatic retries. Awareness remains off. Application startup, lifecycle endpoints, official comments, deliberate client reconnect and actual peer-safe browser undo remain unimplemented or unverified. The earlier narrow upstream hook, comment projection and configured undo proofs also passed. Keep collaboration/comments disabled and omit their controls until all application gates pass.

It uses `YjsThreadStore`/`DefaultThreadStoreAuth` on a validated clone, resolves relative anchors with pinned y-prosemirror mapping and native ProseMirror transformations, and returns only after the existing authorized state transaction. Native overlapping comments use y-prosemirror's exact hashed mark names. Eight native comment checks and four additional real-session database cases cover provenance, author policy, overlapping anchors, stale/foreign selections, limits, concurrent replies, rollback and lock-wait revocation. Room-serialized delivery, HTTP adapters, supplied UI/user resolution and actual collaborative browsers remain activation work.

The prepared transport now serializes server comment commands with inbound edits and joining, applies their complete committed state only after current recipient pruning, and tracks their in-flight work during shutdown. Unknown commit responses invalidate the room cache before reconnect. Bounded stateless metadata exposes only epoch, accepted sequence, ETag and current write permission, never document/thread/session bodies. Application HTTP adapters and real collaborative browsers remain activation gates.

Real HTTP/socket tests with genuine sessions verify native comments, independent version preconditions, concurrent checkpoints, archive/unarchive and immediate old-epoch closure.
