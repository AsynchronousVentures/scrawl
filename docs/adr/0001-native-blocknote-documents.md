# Native BlockNote documents and immutable checkpoints

Scrawl uses BlockNote's standard schema and official shadcn UI rather than maintaining a restricted ProseMirror editor. The authoritative body is BlockNote's native `Block[]`, wrapped by Scrawl metadata `format: "blocknote-json"`, `schemaVersion: 1`, and `editorVersion: "0.55.0"`. BlockNote does not supply an intrinsic JSON schema-version envelope. Scrawl's version identifies its pinned schema contract; the editor version records the producing library baseline. Official server utilities validate native conversion and round trips, alongside strict shape, property, URL and resource checks. The API, history, restore, rendering, outline and native export use the same contract. Linked media blocks are supported now; private upload storage is a separate packet.

Existing snapshots get a finite operator-led representation conversion, never a reset or an automatic read-time converter. The operator backs up original document/revision records privately, proves every payload is representable, then converts all payloads in one transaction while preserving IDs, authors, revision numbers, timestamps and document heads. If conversion would lose content, it stops. This maintenance exception changes encoding, not authored history. A format-specific ETag invalidates clients holding the previous representation. The legacy reader exists only in the upgrade command, not the product runtime.

Today a browser owns its local draft, and explicit Save creates an immutable revision under the existing ETag and authorization transaction. Undo affects the local editor; Discard resets its baseline without any server write. Before collaboration is enabled, durable Yjs state must become a separate live document, not a stream of revisions. An authorized server checkpoint captures native blocks and title atomically; it alone advances the revision head. Shared updates have their own generation and are not described as saved revisions. Server authorization applies to connection, updates, checkpoints, comments, restore and attachment reads, with revocation closing live access. Collaboration uses user-scoped undo; it must not reuse whole-document baseline discard, which could erase other users' edits. Unsent local work can be discarded, while synchronized edits require "Undo my changes". Restore appends a revision and replaces live state through a new server-issued epoch, rejecting stale updates rather than replaying them into restored content. This also addresses the upstream Yjs restore adapter's current lack of restore support. Publication always selects an immutable checkpoint and an attachment allowlist, never a live Y.Doc. These are integration contracts; collaboration, comments and publishing are not implemented by this decision.
